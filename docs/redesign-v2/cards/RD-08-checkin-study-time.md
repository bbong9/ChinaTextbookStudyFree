# RD-08 签到与学习时长宝箱

> 先读 [README](../README.md) 第 1 节全局规则。

**依赖**:RD-03、RD-05、RD-06

## 目标
签到页把**现有**的每日登录奖励可视化成 7 天签到板,另外新增「今日学习时长」计时和 10 / 20 / 30 分钟三档宝箱,学满 20 分钟提醒护眼。

## 范围
### 1. 签到板(左)
- 现有逻辑**不改**:`claimDailyRewardIfDue` 在 `refreshForNow` 时自动入账,金额按有效连胜查 `dailyRewardTable`;补卡后补差额的逻辑(parity-4)也保持原样。
- 签到板只是展示层:
  - 7 格,当前格 = `checkInCycleDay(有效连胜)`(RD-05);
  - 之前的格子盖「✓」章;
  - 第 7 格是大奖格(宝箱)。
- 每格显示该天的奖励:金币数取 `dailyRewardForStreak` 对应的值;第 3、6、7 天另外显示饼干(RD-05 的 `checkInTreats`)。
- 设计稿里的「宠物蛋碎片」**不做**,第 6 天改为显示饼干。
- **今天格子的「领取」按钮**:金币其实已经自动入账,按钮负责「播放领取动画 + 发饼干」。
  - 饼干在这一步才发,用 `lastCheckInTreatDate` 账本防重复;
  - 如果孩子一直没点,第二天打开 App 时补发前一天的饼干,不丢;
  - 点过之后显示「已领 +N」。
- 首页的 `pendingDailyReward` 弹卡改为引导进入签到页:首页弹出一个小气泡「今天的签到奖励到啦」,点击进入签到页。
- 顶部缎带显示「每日签到 🔥 连签 N 天」,N 用 `displayStreak`。

### 2. 学习时长计时(新服务 `Services/StudyTimer.swift`)
- **计入时长的页面**:课本关卡、识字五步、错题复习、课文听读、故事阅读、睡前绘本、数学小火车、英语气球、看图识动物、成语动画播放。
- **不计入的页面**:首页、商店、小屋、签到、家长中心、设置。
- **计时规则**:
  - 页面在前台、App 处于活跃状态时计时;
  - 连续 60 秒没有任何触摸或音频播放,暂停计时;
  - 按秒累加,按本地日期分桶。
- **存档**:`studySeconds: [String: Int]?`(日期 → 秒数),只保留最近 60 天。
- 同步改两端备份(规则见 README 1.1)。
- 家长报告(RD-21)要用每天的分钟数。

### 3. 学习时长面板(右)
- 进度环显示「今日分钟 / 30 分钟」。
- 三档宝箱,状态:
  - 已领:宝箱打开,显示「已领 10 金币」;
  - 可领:宝箱发光跳动,点击领取;
  - 差一点:剩余 ≤ 3 分钟时显示「还差 N 分钟」;
  - 未达到:显示奖励内容。
- 领取调用 RD-05 的 `claimableStudyChests`。账本字段 `claimedStudyChests: [String: [Int]]?`(日期 → 已领档位),只保留最近 7 天。
- 底部一行小字「学满 20 分钟会提醒休息眼睛」。

### 4. 护眼提醒
- 今日学习时长每满 20 分钟,在计时页面上弹出一次全屏柔和提示「休息一下眼睛吧,看看远处 20 秒」,带 20 秒倒计时,倒计时结束可以关闭。
- 由家长中心的「护眼提醒」开关控制,开关在 RD-21 做。本卡先用 `SettingsStore` 新增字段 `eyeCareReminder: Bool`,默认开。
- 关卡进行中弹出时不打断当前这道题:等这道题提交后再弹。

### 5. 首页入口
- 顶部「签到」图标:有可领取内容时显示红点。
- 「今日目标」条(RD-09)和本卡无关,不要把学习时长混进去。

## 验收标准
- AC1 页面和设计稿对比一致(iPhone 16),附截图。
- AC2 单元测试 `StudyTimerTests`:用可注入的时钟验证——前台计时、60 秒无操作暂停、跨午夜分桶、后台不计、60 天裁剪。
- AC3 单元测试:签到饼干每天只发一次;没点领取时第二天补发;补卡前后签到板的显示和实际入账一致。
- AC4 三档宝箱各状态截图;领取后余额和饼干变化正确,重复点击不重复发。
- AC5 护眼提醒:在 UI 测试里通过启动参数把阈值缩短到 5 秒,验证会弹出、20 秒倒计时、关闭后不再重复弹出,直到下一个 20 分钟。
- AC6 现有每日奖励相关测试(`StreakAndEconomyTests`、`WaveBTests` 等)全部通过,数值无变化。

## 审阅重点
- 金币入账的时机没有变(仍在 `refreshForNow`),只是多了展示层。和 Web 端的经济一致性不能被破坏。
- 计时器不在后台跑 `Timer`,用时间戳差值计算,避免耗电。
